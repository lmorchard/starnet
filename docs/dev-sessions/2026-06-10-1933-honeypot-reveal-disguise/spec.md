# Spec — Honey-pot reveal + disguise

## Background

A player loaded a save and saw an owned node labelled `sig-11` they never
exploited. `sig-11` is the `pot/honey-pot` set-piece: it ships
`accessLevel: "owned"` by design (bait). Two features collided to make it
confusing — and one of them left it permanently uninspectable:

1. **Honey-pot is owned-by-default bait.** Intended: a free-looking,
   already-compromised node stuffed with `corp-secrets` to lure the player
   (`data/biomes/corporate-pieces.js`, `honeyPot`).
2. **Identity obscured until probed** (#121). `isObscured(node)` was
   `Boolean(sigAlias) && !probed`. The honey-pot is never probed (PROBE
   requires `accessLevel: "locked"`, and the honey-pot is `owned`), so it
   stayed a permanent `sig-N` mystery with no way to reveal its details.

The invariant #121 relied on — *every node is probed before it is owned*
(`locked → probe → compromised → owned`) — is violated only by the
owned-by-default honey-pot.

## Goals

1. **Reveal fix (done):** an owned/compromised node is never obscured —
   "own it = know it." A node you are inside reveals its identity even
   without a probe.
2. **Disguise:** because the honey-pot now reveals, hide what it *is*. Make
   it masquerade per-run as a loot-bearing node with bait loot, so the reveal
   doesn't telegraph the trap. The rename/retype *is* part of the trap.
3. **Re-arm the trap for realistic play:** an owned node that looks like loot
   is dumped + fetched, not exploited. DUMP must safely bait; FETCH (and MINE,
   closing an existing loophole) must spring the counter-trace. EXPLOIT
   continues to spring it.

## Non-goals

- Changing the obscure-until-probed behaviour for ordinary locked nodes.
- Procedural honey-pot placement, new trap types, or multi-node honey-pots.
- Reworking the loot/macguffin or trace systems beyond what the trap needs.

## Decisions (settled during brainstorming)

- **Reveal rule:** `isObscured` also requires `accessLevel === "locked"`.
  ("Own it = know it"; generalizes to any owned-by-default set-piece.)
- **Disguise identity:** per-run **seeded** pick from a loot-bearing pool,
  limited to **`fileserver` / `workstation`** (plain loot boxes). `cryptovault`
  is excluded — it implies an unlock flow the node won't have.
- **Bait loot:** real-looking macguffins, generated by the normal loot system
  (give the node `lootable` + `lootCount`). They are never collected because
  FETCH springs the trap before payout.
- **Trap trigger:** DUMP baits (safe, reveals the fake loot); **FETCH / MINE /
  EXPLOIT** spring it. Mechanism: a `springTrap()` helper sets `poisoned: true`;
  the existing per-node trigger `poisoned === true → startTrace + log` is the
  shared snap.
- **Trap detection:** a `trap: true` attribute on the node (never shown to the
  player), *not* sniffing the now-overwritten `type`.

## Behaviour

### Reveal (item 1 — implemented)

`isObscured(node)` returns true only when the node has a `sigAlias`, is
**not probed**, **and** `accessLevel === "locked"`. Compromised/owned nodes
reveal their real id/label/type/grade.

### Disguise (item 2)

At `initGame`, alongside the existing macguffin-assignment loop:

- For every node with `trap: true`, pick a disguise `type` from
  `["fileserver", "workstation"]` using the seeded `RNG.WORLD` stream, and
  overwrite the node's displayed `type` and `label` (e.g. a plausible
  `archive-07`-style name). The internal node `id` is unchanged (edges depend
  on it). Glyph follows `type` automatically; the honey-pot has no glyph of its
  own, so this is purely a swap to a believable one.
- The node already carries `lootable` + `lootCount`, so the normal loot loop
  fills it with real-looking macguffins. DUMP reveals them as ordinary loot.

### The snap (item 3)

- `springTrap(nodeId)`: sets `poisoned: true` (the existing
  `poisoned → startTrace` trigger fires the counter-trace + log line).
- `resolveLoot`: if `node.trap` → `springTrap`, mark `looted`, **skip
  `addCash`**, log that the data was bait.
- `resolveMine`: if `node.trap` → `springTrap`, grant **no** exploit reward.
- EXPLOIT: unchanged — the existing `flag on:exploit → poisoned` operator
  already springs it.

### Mission safety (correctness risk)

Mission-target selection MUST exclude macguffins on `trap: true` nodes.
Otherwise a run could choose unobtainable bait loot as the objective and become
unwinnable. Verify the selection site and guard it.

## Set-piece data changes (`corporate-pieces.js`, `honeyPot`)

- Traits: add `lootable`.
- Attributes: add `trap: true`, `lootCount: [1, 2]`; keep `accessLevel: "owned"`,
  `poisoned: false`. (`contents: "corp-secrets"` may stay as flavour.)
- Keep the `flag on:exploit → poisoned` operator and the
  `poisoned === true → startTrace + log` trigger.

## Testing

Reproduce-then-fix discipline; assert observable consequences (per project
testing rules):

1. **Reveal (done):** owned/compromised unprobed node is not obscured; locked
   unprobed aliased node still is. (`node.test.js`, green.)
2. **Disguise is seeded + deterministic:** same seed → same disguise type;
   disguised `type` ∈ {fileserver, workstation}; real honey-pot identity never
   shown.
3. **DUMP baits:** dumping the trap node reveals macguffins, sets `read`, does
   **not** set `poisoned` / start a trace.
4. **FETCH snaps:** fetching sets `poisoned`, calls `startTrace`, and adds
   **no** cash (`addCash` not called / cash unchanged).
5. **MINE snaps:** mining the trap node sets `poisoned`, grants no exploit.
6. **EXPLOIT snaps:** unchanged behaviour still fires the trace.
7. **Mission safety:** trap-node macguffins are never selected as the mission
   target.

Use an explicit seed in every `initGame` test (per project convention / #109).
